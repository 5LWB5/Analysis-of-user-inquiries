# Служба обращений

Учебное веб-приложение для хранения, поиска и анализа обращений пользователей. Приложение создано на Python и Django, данные хранятся в SQLite.

## Возможности

- добавление обращения с темой, описанием и категорией;
- просмотр списка и подробной страницы обращения;
- поиск по теме и описанию;
- фильтрация списка по категории и статусу;
- изменение категории и статуса;
- аналитика по категориям и статусам за выбранный период;
- выгрузка обращений в CSV и аналитического отчёта в TXT;
- административная панель Django.

## Требования

- Python 3.14;
- Windows PowerShell for the commands below.

## Установка и запуск

Клонируйте репозиторий, откройте PowerShell в папке проекта и выполните:

```powershell
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py loaddata demo_tickets
.\.venv\Scripts\python.exe manage.py runserver
```

Откройте в браузере `http://127.0.0.1:8000/`. База `db.sqlite3` создаётся локально командой `migrate` и не хранится в Git. Команда `loaddata` загружает шесть вымышленных демонстрационных обращений, чтобы аналитика не была пустой.

Чтобы создать администратора для панели управления:

```powershell
.\.venv\Scripts\python.exe manage.py createsuperuser
```

Панель администратора находится по адресу `http://127.0.0.1:8000/admin/`.

## Использование

На главной странице можно добавить обращение, найти его по тексту или отфильтровать список. Откройте обращение, чтобы посмотреть описание или изменить его категорию и статус. Страница «Аналитика» показывает статистику; фильтр периода применяется также к скачиваемым CSV и текстовому отчёту.

## Структура проекта

- `support_site/` — настройки и адреса сайта;
- `tickets/` — модель, формы, страницы и аналитика обращений;
- `tickets/migrations/` — схема базы данных;
- `tickets/fixtures/demo_tickets.json` — вымышленные данные для демонстрации;
- `db.sqlite3` — локальная база данных, создаётся при первом запуске;
- `manage.py` — команды управления Django.

## Ограничения учебной версии

Приложение настроено для локальной разработки и демонстрации. Сервер Django для разработки не предназначен для публичного размещения без дополнительной настройки безопасности и production-сервера. В базе нет авторизации обычных пользователей и автоматического определения категории.

Для production задайте переменные окружения `DJANGO_DEBUG=False`, `DJANGO_SECRET_KEY` (новый случайный секрет) и `DJANGO_ALLOWED_HOSTS` (домены сайта). Пример переменных приведён в `.env.example`; этот файл служит образцом и не загружается автоматически. Перед публикацией пройдите официальный чек-лист Django по развёртыванию.
